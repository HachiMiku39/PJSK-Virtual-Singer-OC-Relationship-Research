## 怎样降低读取量，同时保留研究依据

固定使用日文快照`aa934ac00875eae6e89066292fe96c8bd9abb283`，获取4147份文本。对主线、活动、卡牌、区域对白做说话人和场景索引，再对120组关系取候选；不把下载数量称为通读数量。虚拟LIVE、特殊故事、MYSEKAI与自我介绍保存在获取清单，但不进入这一轮候选评分。愚人节区域对白排除于正剧索引。

优化分为四步：按文件哈希复用旧处理结果；以角色发言和明确名字识别候选对象；把引用压缩为带前后文的窗口；复用已有审计事实并合并连续问题。检索排序只决定下一段读什么，**不参与K、C、S、T、B或情感分数**。旧版倍率和2.2次幂不再使用。

对象识别还要检查转述、角色扮演、回忆和第三人的感情。例如“トランポリン”不是指铃；宁宁在戏中饰演的女孩对MEIKO说感谢，不能自动当作宁宁本人表态；穗波转述一歌珍惜Miku，也不是穗波自己的情感。候选资料保留排除标记，允许回查程序错误。

程序不能从台词数量证明独立成长线，不能用多个“谢谢”证明深厚感情，也不能从没有命中推成关系不存在。未核定输入与正式结果分开，更新证据后再改分档。

### 可复现的节省上下文流程

[index_corpus.py](index_corpus.py)只使用Python标准库，缓存目录和原文均放在仓库外。缓存键包含解析器版本与文件SHA-256，修改文件会重新解析，删除路径也会报告；证据ID固定绑定来源哈希及行号。`assessments.json`中的来源已整理为`source_catalog`，正文引用只保留来源ID、行号和审核说明，避免反复复制长链接。

```bash
python3 research/all-characters/index_corpus.py \
  --corpus-dir /path/to/corpus \
  --cache-dir /path/to/cache \
  --output /path/to/review-packet.json \
  --source-commit aa934ac00875eae6e89066292fe96c8bd9abb283 \
  --max-characters 60000 --top-k 4
```

日后新增剧情时加`--changed-only`；核对指定关系时加`--pair '寧々/MEIKO'`。已由人工审核的窗口ID可存为JSON数组，通过`--reviewed-evidence /path/to/reviewed.json`排除重复阅读。缓存命中只证明文本未变，不能自动证明评分正确；首次运行或尚未建立旧索引时，增量模式会检索全部可用文件。

实测本快照有3524份文件进入上述索引范围、约1252万字符。再次运行命中3524份缓存，重新解析0份；未更新时增量包为0条证据。默认预算包选择184个唯一窗口、193次关系引用，证据及引用负载59982字符。该限制**不含完整JSON元数据，不是token计数，也不是通读覆盖率**。严格对象筛选下109组出现检索候选；其余11组须另行扩展词表或回查正文，不记成无关系或0分。

运行验证：`python3 -m unittest discover -s research/all-characters -p test_index_corpus.py`。检查缓存复用、单文件变更、删除提示、审核ID排除、字符预算及角色扮演/词边界。120组公式与来源核验另用`recompute_all.py --corpus-dir /path/to/corpus`；这些程序检查不代替剧情判断。

## 复核与数据使用

从仓库根目录执行：

```sh
python3 research/all-characters/recompute_all.py
```

程序检查120组键唯一、分档边界、强线数到C的换算、两个指数公式、正式结果的复核状态，以及来源ID与引用范围。带`--corpus-dir`时再核对固定文本的哈希和实际行号。检索缓存含全文和上下文，应放在仓库外；仓库仅保存必要的定位、短候选和研究解释。

后续需要逐对完成的复核事项在工作簿状态列显式保留：确认每项分档的直接证据，给独立强线命名、标记重复链，列T的叙事阶段和B的不同帮助类型，并检查同角色另外五位VS的竞争证据。没有完成这些事项，不将114组候选输入标成已核定。

这轮没有启动后台定时研究，也没有把候选表改写成已完成的全角色最终评分。
